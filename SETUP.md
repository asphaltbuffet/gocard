## Library archetype — scaffold divergences to resolve

The shared templates assume a CLI binary. For a library, reconcile these:

- [ ] `mise.toml` `[tasks.build]` injects ldflags into `internal/version`, which does
      not exist in this archetype. Either drop the ldflags (plain `go build ./...`)
      or add an `internal/version` package.
- [ ] `.goreleaser.yml` declares `builds:` + `archives:` + `upx:` for cross-platform
      binaries. A library has no binary to ship — consider trimming to a release-notes-only
      config, or delete goreleaser and let the release workflow publish the tag alone.
      Note `.github/workflows/release.yml` invokes goreleaser-pro.
- [ ] `flake.nix` `packages.default` uses `buildGoApplication` with `mainProgram = "gocard"`.
      Replace with a `checks`/devShell-only flake, or keep it if you later add a demo binary.
- [ ] `CLAUDE.md` "Code Conventions" mentions persistent CLI flags and `--json` output —
      rewrite those bullets for library API conventions.
- [ ] `README.md` shows `go install ...@latest`; for a library prefer `go get`.

## First release

When ready to cut a release:
1. `changie new` — describe changes
2. `mise run pre-release <major|minor|patch>` — batch + merge CHANGELOG
3. Open a PR, merge to main
4. `mise run release` — tag and push (CI publishes the release)
